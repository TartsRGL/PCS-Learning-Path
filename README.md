# PCS-Learning-Path

A structured learning path for building frontend thinking step by step.

PCS starts with meaning.
Then it adds visual response.
Then behaviour, state and interaction.
Finally, it moves toward small application composition.

## 🧭 Path Overview

| Block | Focus | Role |
| ----- | ----- | ---- |
| PCS-HTML | Meaning & structure | What the content is |
| PCS-CSS | Visual response | How the structure reacts |
| PCS-JS | Behaviour & state | How the page behaves |
| PCS-APP | App composition | How the pieces become a product |

## 📚 Learning Blocks

### PCS-HTML

HTML decision-making before layout, styling or behaviour.

Start here if you want to understand why correct structure matters.

### PCS-CSS

CSS as a reaction layer on top of meaningful HTML.

The goal is not decoration first.
The goal is controlled visual behaviour.

### PCS-JS

JavaScript as behaviour, state, interaction and data flow.

PCS-JS builds one growing Project Discovery mini app from L01 to L08.

### PCS-APP

Application-level composition.

This layer is reserved for larger flows, product thinking and complete app structure.

## 🛠️ Method

* One block builds on the previous one
* One lesson adds one clear capability
* Each snapshot should stay readable and functional
* Structure comes before polish
* Behaviour comes after meaning

## 🚀 How to Explore

Clone the repository:

```bash
git clone https://github.com/TartsRGL/PCS-Learning-Path.git
cd PCS-Learning-Path
```

Then choose a block:

```bash
cd PCS-HTML
cd PCS-CSS
cd PCS-JS
cd PCS-APP
```

Start with each block’s own `README.md`.

## 🧠 Why PCS-Learning-Path?

Because frontend problems usually do not start in one language.

Bad CSS often starts with unclear HTML.
Messy JavaScript often starts with unstable structure.
Confusing apps often start without a clear learning sequence.

PCS trains the sequence:

HTML defines meaning.  
CSS reacts to structure.  
JavaScript adds behaviour.  
Apps compose the system.
